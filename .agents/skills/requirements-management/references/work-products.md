# 成果物と記入例

参照章は「実プロジェクトでのテーラリング」、第 2 章 2.4〜2.6 節、第 7 章、第 11 章、第 16 章。記入例は本 Skill のために作成した架空の例。

## 必要な成果物を選ぶ

| 知りたいこと・必要な判断 | 主な記録先と内容 |
| --- | --- |
| 何を変え、何をもって成功とするか | 目的・対象範囲、現状、成功基準、関係者、制約、未決事項。Issue や構想メモにまとめられる。 |
| 要求全体を関係者と確認したい | 要求定義書、または ID でつないだ成果物。背景、根拠、要求・要件、関係者、業務フロー、主要な判断を参照できるようにする。 |
| 個々の要求を継続管理したい | 要求管理台帳。ID、記述、種別、発生源、根拠、優先度、状態、担当、関係、検証、版・変更履歴。 |
| 実現すべき振る舞いを受入可能にしたい | 要件定義、業務・データモデル、受入条件。通常・例外、実現する構成要素、評価方法を必要な粒度で示す。 |
| リスクの高い条件や変更の説明が必要 | 規則の対応表、変更判断・影響、トレーサビリティ、再検証、運用監視、監査証跡。 |
| AI の品質やデータを管理したい | AI 要件、データ定義・来歴、評価結果・基準と版、再評価・停止の条件と担当。 |

既存の台帳や Issue、設計、テストへの参照を使い、項目ごとに正本を決める。独立した文書が必要かは、読者、管理責任、変更頻度、監査の必要性で判断する。

## 要求から変更までの記入例

会計担当者の「締め作業で金額を転記するのに時間がかかる」という指摘から、入力と集計の重複を調べる。次は例示用の ID と記録であり、実案件では実際の記録の参照先を添える。

| 記録 | 記入例 |
| --- | --- |
| 目的 `G-01` | 月次締めの転記を減らす。締めに要する時間を改善指標とし、目標値は現状計測後に会計責任者が決める。 |
| 要求 `R-07` | 会計担当者が指定月の確定済み売上を集計できる。根拠は、現場の指摘と転記手順の確認結果。 |
| 要件 `S-07a` | 会計担当者が対象月を指定すると、取引日が対象月内にある確定済み売上を、その月の集計対象に含める。 |
| 受入条件 `AC-07a` | 対象月の月初・月末の確定済み取引、翌月初の確定済み取引、対象月内の未確定取引を用意する。対象月の集計に、月初・月末の確定済み取引だけが含まれることを確かめる。 |
| 追跡 | `G-01 → R-07 → S-07a → 集計処理 → AC-07a → 検証結果`。実装の参照先と検証結果は確認できた段階で記録する。 |
| 変更提案 `CH-02` | 取引日から入金日への集計基準変更。目的が同じかを会計責任者に確認し、日付の定義・タイムゾーン、分割入金や入金日がない場合の扱い、過去の集計の扱い、表示、月境界の再検証を影響候補とする。 |

## そのまま使える記載項目

- **要求・要件の記録** — ID、種別、上位目的・要求、要求文または要件文、発生源と根拠、優先度と理由、状態と担当、関連先、受入条件と確認方法。継続管理する場合は版と変更履歴を加える。
- **未決事項の記録** — 未確定の対象、現時点の前提、根拠、回答によって変わる要件・検証、判断する人。影響が大きい場合は決定が必要な時点も示す。
- **変更の記録** — 対象 ID と現行版、変更前後、起点と理由、影響先と根拠、確認待ち、決定者と適用版、再検証項目と結果。
- **検証結果の記録** — 要件・受入条件 ID、評価した版と環境、使ったデータと方法、期待値と観測結果、判定、証拠、残件。合意、実装、検証をそれぞれの証拠に基づいて扱う。
